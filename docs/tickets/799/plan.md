# Technical Plan: Admiralty Court (KB) Daily Cause List (#799)

> This plan supersedes the automated spec in the issue comments. That spec concluded a
> bespoke schema/converter/renderer was needed because the field set did not match
> `RCJ_EXCEL_CONFIG`. That was true at the time it was written, but the codebase has since
> grown `libs/list-types/chd-kb-common`, which already implements **exactly** the field set and
> order this ticket mandates. See **Discrepancies vs prior spec** below.

## 1. Technical Approach

`libs/list-types/chd-kb-common` already provides the shared ChD/KB 7-column format:

```
judge, time, venue, type, caseNumber, caseName, additionalInformation
```

That is byte-for-byte the field set and order in this ticket's acceptance criteria and JSON
sample. So this ticket needs **no new schema, no new converter config, no new model type and no
new renderer** — only a thin list-type package that reuses `@hmcts/chd-kb-common` and supplies
its own locale content, PDF template and page.

`libs/list-types/companies-winding-up-chd-daily-cause-list` (issue #803) is the direct
precedent and is already merged. This implementation mirrors it exactly, with one deliberate
divergence: the Admiralty page has **three** "Important information" sections rather than one,
so the page template and PDF template carry three heading/body pairs.

Architecture decisions:

- **New thin package** `@hmcts/admiralty-court-kb-daily-cause-list` under `libs/list-types/`.
  It ships **no `src/schemas/` directory** — the schema lives in `chd-kb-common`. Consequently
  the CI guard test (`libs/list-types/common/src/validation/guard.test.ts`) does not apply, as
  it only inspects packages that ship a schema.
- **Package name is load-bearing.** `validateListTypeJson`
  (`libs/list-types/common/src/validation/list-type-validator.ts`) kebab-cases the DB
  `listTypeName` and dynamically imports `@hmcts/<kebab>`, then picks the first export matching
  `validate[A-Z]`. `ADMIRALTY_COURT_KB_DAILY_CAUSE_LIST` → `admiralty-court-kb-daily-cause-list`,
  which must be the package directory *and* the npm name. The package must therefore re-export
  `validateChdKbListType` under an alias (`validateAdmiraltyCourtKbDailyCauseList`). No
  `PACKAGE_ALIASES` entry is needed.
- **Reference data only in the two TypeScript sources of truth.** No hand-written `.sql`.
  Only `libs/list-types/common/src/list-type-data.ts` is edited — `location-data.ts` needs
  **no change** (see 2.2).
- **Single-variant page handler**: `createSimpleListTypeHandler` from
  `apps/web/src/pages/(list-types)/list-type-handler.ts`, guarding on
  `artefact.listTypeName`. Not `createMultiListGuardAndRender` (that is for one page serving
  several list-type names).
- **No numeric `ListType.id` anywhere** in application code, tests, comments or JSDoc.

### Discrepancies vs prior spec (issue comment)

| Prior spec claim | Reality |
| --- | --- |
| Needs its own schema, Excel converter, model type and renderer | All four already exist in `@hmcts/chd-kb-common` and must be reused, not duplicated |
| Follow `rcj-standard-daily-cause-list` / `court-of-appeal-civil-daily-cause-list` | Follow `companies-winding-up-chd-daily-cause-list`, the ChD/KB precedent |
| References `apps/postgres/prisma/scripts/003_upsert_sub_jurisdictions_and_list_type_links.sql` | That path does not exist; seed SQL is generated by `apps/postgres/prisma/generate-seed-sql.ts` from the two TS data files |
| "Business and Property Courts Rolls Building" must be added to `location-data.ts` | Already present as `locationId: 26`, `regions: [11]`, `subJurisdictions: [10]` |
| `additionalInformation` should be optional | `chd-kb-common`'s schema and Excel config make it **required**; reusing them inherits that. See CLARIFICATIONS NEEDED #3 |

**`conversion/admiralty-court-kb-daily-cause-list-config.ts`** — register the shared config
under this list type's own name:

```typescript
import { CHD_KB_EXCEL_CONFIG } from "@hmcts/chd-kb-common";
import { createConverter, registerConverterByName } from "@hmcts/list-types-common";

export const ADMIRALTY_COURT_KB_EXCEL_CONFIG = CHD_KB_EXCEL_CONFIG;

registerConverterByName("ADMIRALTY_COURT_KB_DAILY_CAUSE_LIST", createConverter(ADMIRALTY_COURT_KB_EXCEL_CONFIG));
```

**`rendering/renderer.ts`** — delegates to `renderChdKbHearingList`, injecting this list
type's own title from its locale files:

```typescript
export function renderAdmiraltyCourtKbDailyCauseList(hearingList: ChdKbHearingList, options: RenderOptions): RenderedData {
  const t = options.locale === "cy" ? cy : en;
  return renderChdKbHearingList(hearingList, { ...options, listTitle: t.pageTitle });
}
```

**`index.ts`** — must export a `validate*` function (dynamic dispatcher requirement), the

## 3. Error Handling & Edge Cases

| Case | Behaviour |
| --- | --- |
| Missing `artefactId` query param | 400 `errors/common` (handler default) |
| Artefact not found / blob missing | 404 `errors/common` |
| `artefact.listTypeName` is a different list type | 400 `errors/common` via `guardArtefact` |
| JSON fails schema validation | 400 `errors/common`, errors logged |
| Unexpected error | 500 `errors/common` |
| Empty hearing array (`[]`) | Renders `t.noHearingsMessage`, no table. Note the Excel converter enforces `minRows: 1`, so an empty list cannot arrive via upload — only via a direct JSON publication |
| Missing Excel column header | Converter rejects the upload with a row-level error |
| HTML tags in any cell | Rejected by `validateNoHtmlTags` in `CHD_KB_EXCEL_CONFIG` and by the schema's no-tag `pattern` |
| Bad time format | Rejected by `validateTimeFormatSimple`; schema pattern accepts `9am`, `10:00am`, `2.30pm` |
| Blank `Additional Information` cell | **Rejected** — the shared config marks it `required: true`. See CLARIFICATIONS NEEDED #3 |
| CSV injection in Excel output | Not applicable unless an Excel generator is added (see #2) |
| Welsh locale | `?lng=cy` swaps title, headers and all three information sections |

## CLARIFICATIONS NEEDED

1. **AC wording refers to the wrong list.** The third AC says "The the Interim Applications
   List (ChD) Daily Cause List is published through the Excel upload route" — that is a
   different list type. Assumed to be a copy-paste error and read as "the Admiralty Court (KB)
   daily cause list". Confirm.

2. **"An Excel downloadable version" — what exactly is expected?** No non-strategic list type
   in this repo has an entry in `EXCEL_GENERATOR_REGISTRY`
   (`libs/publication/src/processing/service.ts`); only SJP and the magistrates lists do, and
   the direct precedent (#803, Companies Winding Up (ChD)) shipped **PDF only**. There is also
   no generic "re-serve the uploaded `.xlsx`" path. Three options:
   (a) treat this AC as already met by the existing upload/PDF behaviour and drop it (matches
   the precedent); (b) add an Admiralty-specific Excel generator; (c) add a shared
   `chd-kb-common` Excel generator and retrofit Companies Winding Up too. **Assumption for
   this plan: (a).** If (b) or (c) is wanted, say so — it is a meaningful addition and would
   change the estimate.

3. **Is `additionalInformation` required or optional?** `chd-kb-common` marks it `required` in
   both the JSON schema and the Excel config, so a row with a blank Additional Information
   cell is rejected at upload. That is existing behaviour shared with Companies Winding Up
   (ChD). Real-world lists often have nothing to add for most rows, so this looks wrong — but
   relaxing it changes the shared package and affects a live list type. Confirm whether to
   leave as-is (this plan's assumption) or raise a separate ticket to make it optional across
   ChD/KB.

4. **Welsh table header for Venue.** pip-frontend's `cy` file has `Leoliad`; the correct Welsh
   is `Lleoliad`, which is what `companies-winding-up-chd-daily-cause-list` already uses. This
   plan uses `Lleoliad`. Confirm — or confirm the pip-frontend value must be reproduced
   verbatim for parity.

5. **Friendly names.** The ticket title says "Admiralty Court (KB)"; pip-frontend's page title
   is "Admiralty Court (King's Bench Division) Daily Cause List". This plan uses the long form
   for `englishFriendlyName` / page heading and the short form for `shortenedFriendlyName`
   (subscription lists, dropdowns), matching how Companies Winding Up (ChD) does it. Confirm.

6. **Subscriptions.** No dedicated work is planned — subscribers to Business and Property
   Courts Rolls Building will pick this up via the existing location-based subscription flow,
   and the email summary is inherited from `chd-kb-common`. Confirm no list-type-specific
   subscription work is expected.
