# Dependency resolutions

`package.json` can't carry comments, so the reason for each `resolutions` pin is recorded here. Remove a pin, and its row, once the upstream fix it's waiting for has landed and the lockfile resolves a fixed version without it.

| Package | Pinned to | Why | Waiting for |
|---------|-----------|-----|-------------|
| `applicationinsights` | `3.17.1` | `@hmcts-cft/cloud-native-platform` 2.3.0, the latest on the hmcts-lib feed, pins `applicationinsights` 3.15.0. That version pulls in `@azure/monitor-opentelemetry` 1.18.1 and OpenTelemetry 2.7.x / 0.218.x, which carry advisories against `protobufjs`, `@grpc/grpc-js`, `@opentelemetry/core`, `@opentelemetry/propagator-jaeger` and `@opentelemetry/instrumentation-pg`, `-mysql` and `-http`. 3.17.1 moves the whole OpenTelemetry set forward (core 2.10, experimental 0.221, `protobufjs` 7.6.6, `@grpc/grpc-js` 1.14.7). | A `cloud-native-platform` release on the hmcts-lib feed that depends on `applicationinsights` 3.17.1 or later. Upstream Renovate has the bump queued on [hmcts/expressjs-monorepo-template#3](https://github.com/hmcts/expressjs-monorepo-template/issues/3). |
| `@opentelemetry/instrumentation-http` | `0.222.0` | [GHSA-3v2p-hm54-8qcq](https://github.com/advisories/GHSA-3v2p-hm54-8qcq) affects 0.204.0 up to 0.222.0. `@azure/monitor-opentelemetry` 1.21.0 (via `applicationinsights` 3.17.1) asks for `^0.221.0`, which can't resolve to 0.222.0. 0.222.0 brings its own `@opentelemetry/instrumentation` 0.222.0 and `@opentelemetry/core` 2.11.0; the rest of the tree stays on 0.221 / 2.10. | An `@azure/monitor-opentelemetry` release that depends on `@opentelemetry/instrumentation-http` 0.222.0 or later, then an `applicationinsights` release that uses it. |
| `js-yaml` | `4.3.2` | `cloud-native-platform` asks for `^4.1.0` and the lockfile had settled on 4.2.0, which has three High advisories (GHSA-2883-xcg3-v3hh, GHSA-52cp-r559-cp3m, GHSA-5p4m-2wfm-xmqj). 4.3.2 is fixed and in range. | A `cloud-native-platform` release that sets its `js-yaml` floor at a fixed version (upstream has a js-yaml 5 bump open in [hmcts/expressjs-monorepo-template#788](https://github.com/hmcts/expressjs-monorepo-template/pull/788)). |

The pins added before this file (`ajv`, `axios`, `body-parser`, `glob` and the rest) were not documented when they were added; add a row when you next touch one.
